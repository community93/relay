## 这一版新增的验证

**有界读**：`workspace.list` 默认只回每个集合的请求**数量**，断言 `collections[].requests` 是数字而不是数组、`totalRequests` 对得上；带 `collectionId` 才展开，展开条数必须等于索引报的数量；`limit:1` 时 `hidden` 等于差额并给出下一步提示；`limit:9999` 被拒且说明范围是 1–500。

**搜索**：`entity.find` 按 URL 片段命中、按中文名称命中、按方法过滤后命中项方法一致；什么都不给时被要求给条件；`limit` 收住结果并回报 `next`。

**干跑预览**：先真发一次留下证据，再断言 `request.preview` ——存在的路径 `ok`、`$.data.nope` 报 `not-found` 且 reason 里同时出现同层的 `items` 与 `total`、`$..bad` 报 `bad-path`、提取器同样被校验、`problems` 恰好 3 条。另外两条是关键性质：预览一个指向白名单外主机的请求**成功**（因为根本不上网，顺带断言同一地址 `request.execute` 会被 `scope` 拒），以及变量解析不出来时 `missingVariables` 列出名字并给出"去环境里定义它"的下一步。

**批量**：一次建三条并逐条回报 `index/ok/data`；混一条坏的方法名，坏的不挡其余且 reason 说清是 HTTP 动词不合法；`commands` 与 `action` 同时出现被拒；嵌套被拒；只读连接下夹一条 `request.upsert` 的批量整批 403 并点名 `commands[1] request.upsert`——而"一条都没执行"是用那条写入真的没落库来证明的，光看返回码证明不了。

**报错自带修法**：未知字段列出允许键、非法 protocol 列出 `"http", "sse", "ws"`、检查规则错误指明 `checks[0].kind`、非法 id 说明字符集、未知实体类型列出可取值。

**中文键路径**：`readPath` 的字段名规则原本是 `[A-Za-z_$][\w$]*`，而 JS 的 `\w` 只吃 ASCII，所以 `$.数据.条目[0].机构` 这类路径**一直解析不了**。放宽成"非结构字符即可"后补了正向与反向用例：中文键能取到值、下标后还能再接中文键、中文键拼错仍然是 miss，且 `$..x`、`$[0];globalThis.bad=true` 这些非法式样照旧被拒（放宽只让原本抛错的路径通过，不会让原本能用的改变行为）。`probePath` 另有独立用例断言它会报出断在哪一段、同层有哪些键。

## 修掉的一处测试脆弱

`e2e_document_design` 的"点击待补充项直接聚焦业务说明"在点击的同一帧读 `document.activeElement`。处理器重渲染时焦点落在后一帧，于是**全套连跑会偶发失败、单独跑必过**——最难查的那一类假回归。改成按帧轮询、上限 1.5 秒后仍然断言焦点（拿不到就失败，不是改成 sleep）。
