# Relay 0.1.16

**AI 连接现在自带 MCP 服务器**，并补上了权限与主机边界的两处缺口：AI 能做的事按档位分权，能访问的地址按名单收口。下载即用，不需要再装或再启动任何 MCP 服务。

## MCP：应用即服务器

开启 **AI 连接** 后，同一个本机端口同时提供两种协议：

| 端点 | 协议 | 适合谁 |
| --- | --- | --- |
| `POST /v1/command` | Relay 自有命令信封 | skill、命令行、`relay_client.py` |
| `POST /mcp` | MCP Streamable HTTP（JSON-RPC 2.0） | 任何支持远程 MCP 的客户端 |

连接面板的 **复制 MCP 配置 / 保存 MCP 配置** 直接给出可粘贴的 `mcpServers` 片段（地址 + `Authorization` 请求头）。面板只显示地址不显示凭证，凭证只在复制和保存时出去。支持 `initialize`、`tools/list`、`tools/call`、`ping`；`GET /mcp` 返回 405，任务进度由客户端轮询 `job_get`。

## 权限分三档，工具表按档位收窄

只读 → 可编辑 → 可执行，高档包含低档，默认**可编辑**（不含执行权）。边界做在传输层而不是文档里：

- 越权调用返回 `insufficient_scope`，并在报错里写明该申请哪一档，模型可以自己去问用户，而不是原地重试。
- MCP 的 `tools/list` **只列出当前档位够得着的工具**：只读连接看不到「发送请求」这个按钮。就算客户端跳过列表直接 `tools/call` 越权工具，传输层仍然会拦下。

## 主机白名单逐跳生效

选**可执行**时必须填写至少一个允许的主机（支持 `*.example.com` 匹配子域）。此前只校验你给的那个 URL，本版把跟随跳转的每一跳也纳入校验——白名单里的服务返回一个指向别处的 302，Relay 会停在半路，并把「重定向目标是未授权主机 X」作为中止原因报回来，而不是带着同一份凭证继续走。跳转失败的原因此前只显示 reqwest 的固定文案「error following redirect」，现在会显示具体是哪一跳、为什么。

`document.verify` 与 `runner.execute` 依然先整批预检，只要有一个端点越界就整个任务拒绝、一个请求都不发。用户在应用里手动点**发送**不受这条限制。
