# Relay 0.1.17

**让外部 AI 一轮就收敛。** 0.1.16 把能力边界守住了，但一个 AI 工具接进来仍然要付三样冤枉钱：先把整个工作区读进上下文、把检查规则写错后要真发一次请求才发现、建十几个接口要发十几趟。这一版把这三样都收掉了。

## 读接口改成"先给地图，再按需展开"

| 动作 | 给什么 |
| --- | --- |
| `workspace.list` | 每个集合带**请求数量**的地图，不含请求明细 |
| `workspace.list` + `collectionId` | 展开指定集合的请求 |
| `entity.find`（新增） | 按名称或 URL 片段跨集合搜索，可按方法过滤 |

三个读接口都接受 `limit`（默认 80、上限 500），被截断时回 `hidden` 和下一步提示，而不是默默少给。`apiVersion` 升到 **3**——`workspace.list` 的返回形状是破坏性变更，`GET /v1/health` 会报出版本。

## 执行之前先干跑

`request.preview` 走和真实发送完全相同的变量、鉴权、集合默认头解析，把真正要上 wire 的东西回显出来（密钥照旧遮掉），**但不发任何流量**。它同时拿 Relay 手上最近一次真实响应逐个校验 checks / extractors 里的 JSON path，按 `ok` / `not-found` / `would-fail` / `bad-path` / `unchecked` 分类回报。

路径写错不再只说"找不到"，而是说清在哪一段断的、那一层有哪些键：

```text
$.data.nope not found — keys at $.data: items, total
```

因为不上网，它也不受主机白名单限制——可以预览一个你根本不允许调用的地址。定在**可编辑**档：它会把凭证解析出来，只读连接不该看到。

## 一次提交多条命令

`{"commands":[...]}` 最多 20 条，顺序执行、一次回包，每条独立报 `{index, ok, data|error}`；坏一条不挡其余，回包点名是第几条。能力分级在传输层**逐条**判：数组里夹一条越权的写入，整批拒绝、一条都不落库。MCP 侧不暴露批量——`tools/call` 天然一次一个工具。

## 报错一律自带修法

所有拒绝现在都说清是哪个字段、回声收到的值、列出可取值或同层键名。之前是 `Invalid auth`、`Unsupported format`、`Unknown field: xyz` 这种，模型只能猜或者重试同一个 payload。

顺带修掉一个真问题：JSON 路径的字段名规则用的是 `\w`，而 JavaScript 的 `\w` 只匹配 ASCII——**中文键的响应用点号形式根本寻不到址**。现在 `$.数据.条目[0].机构` 直接可用。这个产品的接口文档大量是中文键名，属于地基级缺陷。

## 其他

- 权限表新增 `entity.find`（只读）、`request.preview`（可编辑），MCP 工具表随之从 15 项增至 17 项。
- `skills/relay-workflow` 的 Python 客户端加了 `find` / `preview` / `batch` 与 `list --collection/--limit`，并在预览发现问题、批量有拒绝时以非零码退出。
- 回归：AI 连接专项 E2E 从 74 项增至 107 项；`cargo test` 59 项；检查与路径单测 66 项；原生回归 936/936、网络回归 306/306。
