# Relay 0.1.14

HTTP 请求新增「检查与提取」，把接口请求成功与业务检查通过分开。登录请求提取出的 token 可以在本次运行计划中传给后续接口；每条结果保存当次请求、响应以及检查证据。

- 表单式检查：允许的状态码、JSON 路径存在 / 相等 / 类型、响应耗时。可明确预期 401 等错误状态。
- 从 JSON 字段或响应头提取变量；默认只在本次计划生效。提取或检查失败不会继续使用旧值，结果可主动写入执行时的环境。
- 响应树直接添加提取规则，特殊 JSON 键名的路径复制准确。结果默认隐藏提取值。
- 手动发送、计划运行、文档验证使用相同的规则。HTTP 200 但业务检查失败时，文档不会标为已验证，也不会覆盖上一份验证样例。
- OpenAPI 3 JSON / HAR 本地导入预览：选择请求、修改标题、指定集合、默认排除敏感头和参数，保留 HTTP / SSE / WS 协议。
- 取消单独记录，计划开始时固定环境；不同计划、不同轮次的提取变量互相隔离。
- 检查证据按容量保留，连续通知最多显示三条，导入目标使用统一的主题菜单。

Windows 10 / 11 x64。安装附件：`Relay_0.1.14_x64-setup.exe`。

OpenAPI 导入目前支持 JSON，不支持直接读取 YAML 或远程 `$ref`。文件与二进制请求体需手动配置；复杂参数、安全方案和不支持项会在预览中提示。HAR 请求体可能包含业务数据或凭据，发送前应检查。

本版本完成第一阶段的检查、提取与导入。批量文档验证、契约漂移检测、AI 流式阅读和响应对比仍未实现。

操作见[请求检查与变量链路](../request-checks.md)，发布前验证见[0.1.14 测试记录](../testing-v0.1.14.md)。
