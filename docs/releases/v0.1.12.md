# Relay 0.1.12

修复 WS / SSE 导入后进入 HTTP 面板，以及 WebSocket 连接配置与请求认证脱节的问题。

导入入口统一使用 cURL，移除外部集合文件的导入入口及粘贴识别。项目说明仅介绍 Relay 自身的功能。

- cURL 导入预览显示每条请求的协议，可在 HTTP、SSE、WS 之间调整。根据 WS 地址、握手头、SSE Accept 头和 JSON 的 `stream: true` 推断协议，手动选择优先。
- WS 握手沿用环境 / 集合 Headers、Auth 与变量解析；客户端重新生成 Host、Upgrade、连接密钥等握手头，避免复制的旧头与自动生成的头重复。
- WS 增加 Auth、握手超时和 SSL 校验设置；认证随请求保存。子协议及发送消息支持变量；服务器关闭时显示关闭码与原因。
- “发送一帧”改为“发送消息”，文本和 Base64 二进制类型使用中文标签。Ctrl+Enter 发送消息，发送计数在写入成功后更新；消息流页签数量同步更新。
- 接收与发送公平调度，自动回应服务器 Ping；握手拒绝显示 HTTP 状态与认证检查位置。
- 文档 cURL 草稿进入调试时使用对应协议；文档运行验证明确提示当前仅支持 HTTP。
- 弹窗的默认焦点不会覆盖已经开始编辑的输入框。

仅有 `curl -N` 或路径名无法可靠判断协议，可在导入预览手动选择。Socket.IO 等应用协议仍需按服务端约定握手和发送消息。
