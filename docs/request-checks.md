# 请求检查与变量链路

在 HTTP 请求的「检查与提取」中添加规则，保存请求后，手动发送、运行计划和关联文档的运行验证使用同一份规则。

## 检查

| 检查项 | 示例 | 含义 |
| --- | --- | --- |
| 状态码 | `200, 201` | 接受其中任意一个状态；可明确填写 `401` 检查鉴权拒绝 |
| JSON 字段存在 | `$.data.id` | 存在即可；`0`、`false`、`null` 都不是缺失 |
| JSON 字段相等 | 路径 `$.code`，预期 `0` | 预期使用 JSON：字符串写为 `"ok"`，布尔值写为 `true`；对象比较不要求键的排列顺序一致 |
| JSON 字段类型 | `$.data.items` → `array` | 支持 string、number、boolean、null、object、array |
| 响应耗时 | `1000` | 整个 HTTP 请求的耗时上限，单位 ms；不等同于 DNS、TLS 或首字节计时 |

JSON 路径支持 `$`、`$.data.id`、`$.items[0].id` 和 `$["a.b"]`，不执行表达式、通配符或过滤脚本。相等检查的预期值支持 `{{变量}}`，在发送前解析。配置错误、无效 JSON 和截断响应会明确失败。

未配置状态码规则时，HTTP 200–399 且无执行错误才算请求成功；其他已启用的检查和变量提取也必须通过。配置了状态码规则时以该规则为准，因此预期的 401 可以通过，网络失败无法通过。

## 登录后传递 token

1. 登录请求返回 `{"data":{"token":"…"}}`，添加提取：变量名 `token`，来源 JSON 字段，路径 `$.data.token`。也可从响应树点击「提取」，自动带入路径。
2. 后续请求在 Auth 或 Headers 中引用 `{{token}}`，把登录请求排在计划前面。
3. 运行计划。在每条执行详情的「请求」中查看本次解析值与来源，在「检查」中查看预期、实际和提取结果。

变量只在本次计划中生效，优先于环境、集合和全局变量；不同计划、不同轮次之间隔离。提取失败或业务检查未通过时，该步骤声明的输出变量不会沿用旧值，后续引用会提示缺失。手动发送会展示提取结果，但不会隐式修改其他请求的作用域。

需要长期保存时，执行结果中点击「写入环境」。写入对象是**执行时的环境**，之后切换环境不会改变写入目标。结果默认隐藏提取值，可以主动显示。请求、响应和执行历史存储于本机，仍应妥善保管数据目录。

计划开始时固定所选环境；每个请求发送前固定自己的检查配置。运行中修改规则不会改变已经发送的请求的判定。取消、跳过、变量缺失、网络失败和检查失败分别记录。

## 与交付文档联动

关联集合请求的文档在验证时也执行其检查。HTTP 200 但业务检查失败不会标为已验证；不会覆盖上一份验证样例，也不能确认交付。文档的「检查」页显示当次失败证据。这个版本尚未实现批量验证、远端契约漂移检测或定时文档监控。

## OpenAPI / HAR 导入

从顶部「导入」或命令面板打开。支持 OpenAPI 3.x **JSON** 和 HAR JSON，文件上限 16 MiB；YAML 需先转换为 JSON。

- 导入前选择请求、修改请求名和目标集合名，确认后才创建请求；不会自动发送。
- 默认排除名称匹配凭据的请求头和参数；HAR 的 URL 账号密码也默认排除。请求体不会全面自动脱敏，发送前检查其中的业务数据与凭据。
- 保留 HTTP / SSE / WS 协议。HAR 可根据 URL、请求头、流式请求体及响应媒体类型识别协议。
- OpenAPI 支持文档内 `$ref`；不下载外部引用。参数示例、默认值、JSON 请求体示例及常见表单字段可导入。缺少示例的请求体留待填写，不从 schema 编造业务值。
- 多服务器、多请求体格式只选取一种；复杂参数序列化、OAuth 等安全方案、文件与二进制上传、Callback / Webhook 会提示手动处理。导入预览列出具体限制。

原有 cURL 导入和集合 JSON 导出保持可用。
