## AI 到交付的真实流程

外部 HTTP 客户端创建集合与 cURL 请求 → 配置状态码/JSON检查 → Relay 真实执行 → 关联交付文档 → 批量验证 → 根据真实样例补写字段 → 用户在应用中确认交付 → Python 客户端导出 HTML。

同时验证 Markdown 和 OpenAPI 导出，保存后的协议、检查、字段说明、执行结果在应用重启后恢复。导出的 HTML 已用浏览器实际渲染，检查版式、横向溢出和敏感值展示。

关键边界包括：

- 未认证、错误凭证和浏览器 Origin 拒绝访问；关闭连接后旧端口失效，新连接轮换凭证；超过2MiB请求拒绝。
- 更新必须匹配版本；已有未保存草稿，以及 AI 保存期间新输入的请求或文档内容，都不会被覆盖。
- HTTP200但业务断言失败返回失败状态，保留上次成功样例，并撤销原交付确认；客户端以非零退出码报告业务失败。
- 登录提取 token 后串行验证，不向 AI 输出原始凭据；取消后再次执行，旧响应不会覆盖新结果。
- WS/SSE 导入保留协议；不支持的自动流式执行明确报错。文件路径上传配置不通过自动化接口接收。
- URL 与 Params 的同名参数去重；其他重复参数如 `tag=a&tag=b` 保留；URL 中的查询参数生成文档字段。
- AI 接口拒绝伪造验证时间与交付确认，导出前返回实际审核状态。
